# Publish 模块

## 职责与边界

`apps/publish` 管理本地发布草稿、三张封面候选、任务/视频/封面/平台指纹和抖音、小红书发布安全状态。它只消费已生成视频，不参与音色、口型或源视频处理。

当前实现包含可信生成视频历史、受控视频预览、三个独立封面候选的评分选择、官方 HTTPS 主机精确校验和一次性提交令牌状态机；状态不确定后禁止再次确认。发布准备只接受任务日志中已完成的 `video.lipsync` 固定受管输出，选择和确认时都会重新计算视频 SHA-256，并在确认前重新校验选中封面哈希；缺失或哈希不符的历史记录保留为显式不可用状态，不允许预览或选择，用户可重新生成或在再次复验失败后移除该失效任务记录。Worker 本地抽帧并渲染三张 PNG，以亮度和边缘清晰度推荐候选。草稿绑定任务、视频和封面哈希并原子持久化，使用 revision 阻止旧页面覆盖；重启可恢复草稿，提交中或等待用户的草稿恢复为状态不确定。标题、简介、话题、平台或封面变更会使旧确认失效。人脸避让评分、受管浏览器会话、平台 DOM 适配和真实上传仍未落地，不得据此报告可一键发布。

## 关键入口与公共面

| 路径                             | 职责                                                |
| -------------------------------- | --------------------------------------------------- |
| `main/contracts.ts`              | 草稿指纹、封面候选、域名和单次提交状态机            |
| `main/draft-repository.ts`       | 草稿原子持久化、编辑版本和确认指纹                  |
| `main/service.ts`、`main/ipc.ts` | 可信生成历史、受控视频选择、本地文案/封面和窗口授权 |
| `renderer/routes/workbench.tsx`  | 独立“发布视频”路由、历史预览与发布内容              |
| `types/`、`preload/index.ts`     | 平台能力、视频选择和草稿准备 bridge                 |

平台资料目录必须位于 `userData/talkhero/browser/<platform>`，不得读取日常浏览器 profile。登录、扫码、验证码、风控、页面变化和结果不确定必须暂停或失败；实际提交只能来自用户对当前草稿的一次明确触发。

用户界面不定义独立窗口；`/publish/workbench` 以“发布视频”菜单复用原系统 `setting` 窗口和 `SettingLayout`。页面选择来自已验证的当前或历史生成视频，并在同页提供预览、封面文案、平台选择和发布准备；当前窗口生命周期内保留已选视频、草稿、未保存编辑和进行中锁定，持久化草稿仍以 main 侧存储为准。全部 publish IPC 只接受受信 `setting` 窗口。

## 验证与维护

目标测试：`pnpm exec vitest run apps/publish`。真实页面验收默认停在最终提交前；实际提交必须针对授权测试内容另行明确触发。Mock 或 fixture 不能证明平台成功。

草稿结构、指纹、平台域名、状态机、浏览器资料、选择器或提交成功信号变化时更新本文件。通用策略见 [测试策略](../../docs/testing.md)。
