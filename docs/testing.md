# 测试策略

测试以降低真实回归风险为目标，优先保护状态机、IPC 策略、认证/支付、持久化、文件协议、快捷键、权限、平台桥接和历史 Bug。覆盖率只用于发现盲区；不要求每个文件、函数或组件都有测试。自动化不能替代真实桌面环境验证。

## 当前能力

| 能力 | 状态 | 命令或位置 | 说明 |
|---|---|---|---|
| Vitest | 已具备 | `vitest.config.ts`、`apps/**/*.test.ts` | Node 环境；包含单元、契约和部分集成测试 |
| 目标测试 | 已具备 | `pnpm exec vitest run <test-file-or-directory>` | 优先运行最接近改动的文件或模块 |
| 全量测试 | 已具备 | `pnpm test` | `vitest run` |
| 类型检查 | 已具备 | `pnpm typecheck` | Node 与 Web TypeScript 配置 |
| 静态分析 | 已具备 | `pnpm lint` | ESLint |
| 构建 | 已具备 | `pnpm build` | 包含原生构建、类型检查和 electron-vite 构建 |
| 桌面真实运行 | 已具备 | `pnpm dev`、`pnpm start` | 必须按受影响平台与硬件验证 |

现有测试重点覆盖 auth 契约/流程、core request/shortcut/Tray，以及发布别名脚本。

## Spec、Plan 与风险型 TDD

`_specs/` 决定测试应证明什么，每条重要 `AC-*` 必须映射自动化测试或真实验证；`_plans/` 只安排顺序和影响范围，测试不得锁定其内部实现细节。Spec 不明确时先澄清。

| 验收项 | 风险 | 自动化测试 | 真实验证 |
|---|---|---|---|
| AC-* | 高 / 中 / 低 | 测试路径或“不适用” | 平台、步骤与证据 |

- 高风险：认证、支付、权限、持久化、文件写入、原生桥接和不可逆行为。成功路径及高影响失败路径必须有证据，适合自动化时必须自动化，并补真实环境验证。
- 中风险：普通业务规则、状态、网络、文件、缓存、超时、常用交互和平台差异。验证主要行为与重要失败路径，组合低成本自动化和真实运行。
- 低风险：文案、纯样式、类型、静态配置和无判断装配。通常依赖类型、lint、构建或简单运行；发生过回归时提高等级。

对稳定可自动化的高风险行为、状态转换、边界输入和 Bug 回归执行：先写测试并确认其因目标行为缺失或旧 Bug 正确失败，再做最小实现使同一测试通过，运行相关回归，必要时局部重构并复验。编译错误、坏 fixture、路径错误或环境未启动不算 Red；不得跳过、删除、弱化断言或过度 Mock 制造 Green。

测试应验证可观察行为，独立、可重复、不依赖顺序，并控制时间、随机、网络、文件和全局状态。可以 Mock Electron/系统 API、网络与硬件边界，但不得 Mock 被测试的核心判断；测试结束后恢复 fake timer、全局 Mock 和环境变量。不得使用生产凭据、授权码、支付或个人数据。

## 执行与真实验证

| 改动类型 | 必需验证 |
|---|---|
| 低风险 | 最小相关类型、lint、构建或运行检查 |
| 普通业务 | 目标测试、相关回归、`pnpm typecheck`、`pnpm lint` |
| 高风险 | 有效 TDD/替代证据、相关测试、类型、lint、必要构建、真实平台验证 |
| Bug 修复 | 旧行为上能失败的回归测试，或说明无法自动化及替代步骤 |
| 发布前 | 全量测试、类型、lint、适用平台构建与关键桌面冒烟 |

装配或打包变更按需增加 `pnpm build`、`pnpm build:web:win`、`pnpm build:web:mac` 或 `pnpm check:web:mac`。安装、签名、公证和官网真实服务必须在受支持平台验证；未执行的平台不能写成通过。

真实运行记录必须包含环境、前置条件、操作、预期、实际结果、是否通过、未验证项与原因。没有单一 `verify` 时，按风险执行上述等价本地门禁。失败须区分本次回归、既有问题和环境阻断，不得忽略退出码或依赖长期重试。

当前最高价值待建设项是覆盖应用启动与少量核心跨进程流程的稳定桌面冒烟入口；只在收益足以覆盖维护成本时建设，不引入覆盖率配额或大型测试矩阵。
