# 后盾云独立代码审查

默认只读。先完整读取 `../../../AGENTS.md`、相关已确认 Spec、Plan、模块 README、目标 diff 和验证证据。用户明确要求“审查并修复”时才在审查完成后最小修复 P0/P1；P2/P3 需另行指定。不得格式化、暂存、提交、推送、合并、发布、迁移或扩大为全仓重构。

按用户指定文件、目录、提交、分支或 diff 定范围；未指定时审查当前已暂存、未暂存及相关未跟踪文件。检查完整调用链，不只看孤立 diff：

- Spec AC、用户可见行为、状态转换和失败后的数据一致性。
- Electron main/preload/renderer 隔离；IPC sender、窗口、权限和不可信参数在 main 校验；preload 保持最小 bridge。
- `config/main.ts`、`config/preload.shared.ts`、`config/preload.ts`、`config/routes.ts`、`config/window.ts`、`config/tray.ts`、`config/menus.tsx` 的必要装配同步。
- 认证、支付、授权码、更新、文件/持久化、媒体权限、全局 Hook、原生 addon、PowerShell worker、计时器、监听器、窗口与媒体流的安全和生命周期。
- macOS 15+ arm64 与 Windows 11 x64 的真实差异；`apps/window-layout` 和明确标注的模块不支持 Linux。
- 新增防御分支是否有 Spec、契约、失败测试或真实证据；标出吞错、错误返回成功、重复上游校验与掩盖缺失状态的默认值。

测试和验证只选择能证明结论的最小集合：适用目标测试、相关回归、`pnpm typecheck`、`pnpm lint`，必要时构建或真实桌面验证。昂贵、签名、真实支付、生产服务或长时间验证不默认执行；未运行不得写成通过。项目采用风险型 TDD 时检查 Red 是否因正确原因失败；缺少历史 Red 本身不自动构成问题。

严重度：P0【高危】为数据不可逆损坏、严重安全/隐私、支付/认证关键错误或核心系统不可用；P1【高危】为主要功能错误、AC 缺失、常见崩溃、支持平台不可运行或确定性高影响回归；P2【低风险】为有限但真实的中等影响问题，最多三项且不阻断；P3 默认省略。P0/P1 阻断交付并给最小修复方向；低风险只提醒，不给修复代码。同一根因合并报告。

输出顺序：P0/P1/P2 发现（路径:行、触发、影响、证据）、实际验证、范围与未验证风险、结论。结论只用“通过 / 修复后通过 / 不通过 / 无法完成审查”；没有 P0/P1 时明确未发现阻断问题。中高风险 SDD 交付必须由未参与实现的独立上下文使用本 Skill；自审不能冒充独立审查。
