## 1. 背景与目标

- 当前问题：仓库现有 Electron 脚手架只有 core、auth、secret 等通用能力，没有本地模型运行、音色档案、文案转语音、视频人物跟踪、局部口型生成、封面生成或平台网页发布能力。
- 目标用户：拥有本人或已取得单独授权的人脸与人声素材，希望在本机快速制作 3 分钟以内口播短视频并发布到抖音、小红书的创作者。
- 功能目标：用户可在软件内一键安装全部应用受管资源；在独立“视频音色”页面从 B 视频创建或更新音色，在“生成视频”页面依次使用音色库与文案音频并处理 A 视频，在独立“发布视频”页面选择及预览当前或历史结果、生成发布资料；由用户明确点击抖音或小红书后自动完成对应平台网页上传、填表和提交。
- 总体完成定义：四个新模块按约定装配；核心流程、失败与恢复状态可观察；默认模型为 IndexTTS 2.5 与 MuseTalk 1.5；合格素材能在真实 Windows NVIDIA 环境完成端到端生成；抖音、小红书发布适配器能在不绕过登录或风控的前提下执行；自动化、类型、lint、构建、真实运行和独立审查达到本 Spec 的交付门禁，或对缺失的外部/硬件验证明确披露而不虚报通过。

## 2. 模块归属

- 类型：新模块、跨模块功能。
- 目标 `apps/<module>` 或业务域：
  - `apps/inference`：本地 Python Worker、模型与媒体工具、硬件检测、资源调度及任务协议。
  - `apps/voice`：B 视频预处理、音色档案生命周期、文案转音频与试听。
  - `apps/video`：A 视频质检与目标人物选择、跟踪、口型、局部融合和视频输出。
  - `apps/publish`：标题、简介、话题、封面和抖音/小红书网页发布。
- 判断依据与相邻边界：`apps/core` 继续只提供窗口、store、系统和共享 Electron 基础设施；`apps/auth` 的登录与订阅语义不变；AI 模型和 FFmpeg 不进入 Electron renderer/main 的执行上下文；ASR、FFmpeg、封面以及单个平台只是上述模块内部适配器，不新增 app。

## 3. 范围与非范围

### 范围内

- Windows 11 x64 + NVIDIA CUDA 的环境检测、受管本地 Python Worker、模型/工具安装状态与任务资源调度。
- 在“本地推理”页由用户点击一次“安装所需资源”后，软件自动按固定清单下载、校验并原子安装受管 Python 3.11、Python 依赖、模型权重、ASR、FFmpeg/ffprobe 与受管浏览器；显示总量、磁盘需求、许可证入口、分项进度、取消、重试与修复。NVIDIA 驱动等系统级前置条件只检测和引导，不静默安装或修改系统 Python。
- 从 10～60 秒 B 视频创建本地音色档案，推荐 15～30 秒；自动提取音轨、筛选有效单人语音、基础清理、自动转写、试听和保存。
- 音色档案的列表、试听、重命名、更新与删除；同一音色在后续任务中复用且不要求再次上传 B 视频。
- 使用 IndexTTS 2.5 从已保存音色和独立文案生成音频，支持自然、热情、沉稳、讲解等有限语气及合理语速控制、分段生成、试听与保存。
- 对不超过 3 分钟的 A 视频执行媒体校验、人脸质量检查、单个目标人物选择与身份锁定；支持坐姿、站立和正常走动。
- 使用 MuseTalk 1.5 的 256×256 内部人脸工作区生成口型，只融合嘴部及自然过渡所需的最小邻域并输出原规格视频。
- 在独立“视频音色”页面完成音色创建、更新及授权素材选择；在“生成视频”页面先完成音色库/文案音频，再完成 A 视频对口型和当前结果预览；在独立“发布视频”页面完成历史/当前生成视频选择与预览、发布资料编辑和平台发布。
- 视频生成成功后自动选中并在页面内预览；历史列表只展示任务记录中已完成且受管输出仍存在并通过指纹复验的视频，缺失或损坏项显式不可用。
- 选择保留 A 视频环境声并混合新语音，或以新语音替换原音轨；选择必须显式，不覆盖源文件。
- 生成任务的排队、进度、取消、阶段检查点、有限重试、失败片段报告和同一 A 视频跟踪缓存复用。
- 根据文案生成可编辑的标题、简介和相关话题；从视频抽帧并使用本地模板生成 3 张候选封面，自动推荐 1 张。
- 使用应用受管的独立浏览器资料目录，分别适配抖音和小红书创作者页面；用户明确触发后自动打开页面、上传视频与封面、填写表单并点击提交。
- 登录、扫码、验证码、风控和状态不确定时暂停或失败，不绕过平台控制；仅在页面给出可验证成功状态时报告提交成功。
- 人脸、人声授权确认、AI 内容声明入口、本地隐私、敏感日志过滤与受管数据删除。
- 四个新模块的 README、最小 preload/IPC 公共类型、主窗口/路由和必要 `config/` 装配。

## 5. 目标行为与流程

### 主流程

1. 前置条件：用户进入原系统 `setting` 窗口的“本地推理”菜单；操作：查看检测结果并点击“安装所需资源”；状态变化：软件检测平台、GPU、驱动、磁盘和已有资源后，自动按受信清单下载、校验并原子安装全部应用受管资源；可观察结果：明确显示安装总量、分项进度、当前阶段、取消、失败原因、重试和修复。系统级 NVIDIA 驱动缺失时停止并给出人工安装指引。
2. 前置条件：环境可支持音色创建；操作：用户进入原系统 `setting` 窗口的独立“视频音色”菜单，确认拥有授权并选择 B 视频；状态变化：受控路径经 main 校验后进入 voice 任务；可观察结果：显示媒体/人声质检、转写、试听和可命名音色档案，并可在该页更新已有音色参考。
3. 前置条件：已有音色；操作：用户进入“生成视频”页面，在“音色库与文案音频”区域选择音色、输入文案并选择语气、语速；状态变化：voice 调用 inference 分段生成音频；可观察结果：用户能试听、重做或确认音频，B 视频无需再次提供。
4. 前置条件：音频已确认；操作：用户在同一个“生成视频”页面继续选择 A 视频、音轨处理方式和目标人物；状态变化：video 完成媒体质检、人物跟踪、局部口型、融合、音频合成和输出；可观察结果：用户获得不覆盖源文件的原规格视频，生成成功后自动选中并在页面内播放预览，同时能看到进度与失败片段。
5. 前置条件：至少存在一个成功生成的视频；操作：用户进入独立“发布视频”页面选择刚生成或历史生成视频；状态变化：系统复验完成任务、受管路径和文件指纹，publish 为所选视频生成并保存可编辑文案及 3 张封面；可观察结果：视频预览、推荐封面和所有将提交的字段属于同一个已校验视频。
6. 前置条件：发布资料已确认；操作：用户仍在“发布视频”页面选择抖音或小红书并点击对应“一键发布”；状态变化：平台适配器启动/复用独立浏览器会话并执行上传、填表和提交；可观察结果：显示等待登录/人工验证、提交成功、失败或状态不确定，不把提交成功误报为审核通过。

### 关键失败流程

- 环境、模型、工具或磁盘不满足要求时阻止对应任务，显示缺失项与可恢复操作，不进入无意义重试。
- 一键安装中任一资源下载中断、哈希不符、许可证信息缺失、解压越界或磁盘不足时停止在明确分项，未校验资源不得进入可用目录；已完成且仍通过校验的分项可在重试时复用。
- B 视频无音轨、超出时长、没有足够有效单人语音或转写失败时不创建音色档案，不保留半成品为可用音色。
- 文案为空、超过可处理上限、生成内容与文案不一致或音频时长无法在合理语速内适配 A 视频时，阻止口型任务并允许修改文案/语速或重新生成。
- A 视频超时长、格式不支持、目标人物无法可靠识别，或可用人脸时段不足时，不启动口型或将风险时间段明确标出。
- 运行中跟踪丢失、遮挡、严重侧脸或模糊时，不扩大生成区域；保留原帧并记录失败片段，最终结果必须带质量警告或阻止“合格”状态。
- Worker 崩溃、OOM、模型损坏、工具失败、取消或磁盘不足时，任务进入明确终态，释放资源并保留可复用的已完成阶段。
- 发布遇到未登录、验证码、扫码、风控或平台确认时暂停等待用户；DOM/URL 不匹配、上传失败或提交结果不确定时停止，不自动重复点击提交。
- 历史视频记录对应文件缺失、损坏、越出受管输出目录或指纹不符时禁止预览与发布，并提供重新生成或移除失效记录的明确操作。

### 恢复流程

- 环境安装失败可从已校验下载点重试；损坏资源先隔离再重新下载，不复用未校验文件。
- 音色创建失败可更换 B 视频；成功音色不因后续音频/视频任务失败而损坏。
- 生成任务按阶段保存检查点；重试从最后一个完整且输入指纹一致的阶段开始，输入变化后旧检查点失效。
- 取消向 Worker 发送受控取消并在超时后终止该任务进程；UI 等待主进程确认终态，不伪造即时取消成功。
- 发布暂停后只能由用户对同一任务点击继续；状态不确定的任务要求用户先核对平台作品列表，软件不自动重发。

## 6. 需求清单

### 功能需求（FR-*）

- FR-001：不新增或保留独立 TalkHero 工作台窗口；原系统 `setting` 窗口作为唯一主界面，继续使用既有 `SettingLayout`。业务菜单为“视频音色”“生成视频”“发布视频”和“本地推理”，并保留原有“帐号订阅”“更新软件”“系统配置”。“视频音色”只承载创建或更新音色；“生成视频”承载音色库/文案音频和 A 视频对口型；“发布视频”承载历史/当前视频选择、预览、发布资料与双平台发布。
- FR-002：`apps/inference` 通过有版本的结构化协议管理独立 Python Worker，检测 Windows、NVIDIA GPU、CUDA/驱动、显存、磁盘、模型、ASR、FFmpeg 与浏览器资源；用户点击一次“安装所需资源”后，软件自动完成全部应用受管资源的固定清单下载、逐项哈希校验、原子安装和可用性复检，并提供总量、分项状态、进度、取消、错误、重试和修复。不得自动安装 NVIDIA 驱动、修改系统 Python 或执行清单外安装命令。
- FR-003：用户确认人脸与人声授权后，可从 10～60 秒 B 视频创建音色；系统自动提取和清理有效单人语音、自动转写、生成试听并保存命名档案。
- FR-004：音色库支持列表、试听、重命名、更新和删除；后续生成从档案读取参考音频、转写和特征，不再要求 B 视频。
- FR-005：用户选择音色、输入独立文案、选择有限语气和合理语速后，IndexTTS 2.5 分段生成内容严格来自文案的可试听音频；确认的音频可被保存和复用。
- FR-006：用户上传不超过 3 分钟的 A 视频后，系统显示格式、时长、画幅、帧率、人脸大小/清晰度/角度/遮挡/出画/模糊质检和人物候选，并要求用户明确选择一个目标人物。
- FR-007：MuseTalk 1.5 以 256×256 内部人脸区域驱动口型，跟踪坐姿、站立或正常走动的目标人物，并只将嘴部及必要最小过渡区融合回原始帧。
- FR-008：用户必须选择“保留环境声并混音”或“使用新语音替换原音轨”；输出写入新文件，默认保持 A 视频画幅、分辨率、帧率和时长，不执行其他视频处理。
- FR-009：生成任务显示阶段、进度、预计剩余状态、取消、失败原因与失败片段；同一 A 视频输入指纹一致时可复用人脸跟踪缓存和完整检查点。
- FR-010：视频生成完成后在“生成视频”页面自动选中结果并以内嵌播放器预览；“发布视频”页面列出以前成功生成的视频，选择时复验任务终态、受管输出路径、文件存在性和指纹。根据所选视频及已确认文案在本地生成可编辑标题、简介和相关话题；从所选视频抽帧，以本地模板生成 3 张独立封面并推荐评分最高的一张。
- FR-011：抖音和小红书分别使用应用受管的独立浏览器资料目录保存登录状态；用户在“发布视频”页面选择所需历史/当前视频和目标平台后，发布前完整展示平台、视频预览、封面和表单内容。
- FR-012：只有用户对当前所选视频和平台明确点击对应“一键发布”后，平台适配器才可打开官方创作者页面、上传视频与封面、填表并点击提交；每个平台独立校验域名、页面和字段。
- FR-013：平台登录、扫码、验证码、风控和用户确认触发暂停；提交状态被区分为未开始、准备中、等待用户、提交中、提交成功、失败、状态不确定和已审核（仅当页面可验证）。
- FR-014：创建音色与发布前提供授权/AI 内容声明；导出和发布元数据按实现时适用规则标识，同时保持“仅嘴部处理”的产品边界，不未经 Spec 扩大可见画面修改。
- FR-015：所有 A/B 视频、音色、文案、音频、输出、浏览器资料和任务状态默认本地保存；提供明确的受管数据删除，不上传到 TalkHero 或第三方推理服务。

### 边界与异常（EDGE-*）

- EDGE-001：B 视频少于 10 秒、超过 60 秒、无音轨、有效人声不足、多人重叠、背景音乐/回声/爆音导致不可用时拒绝创建；可接受但非最佳的质量只给出警告并要求用户确认。
- EDGE-002：A 视频超过 3 分钟、损坏、格式/编解码不支持、无可用人物或多人但未选择目标时拒绝生成。
- EDGE-003：文案为空、仅空白、超出 3 分钟可合理承载的时长，或目标音频长于/短于视频且无法通过已允许语速自然适配时，不静默裁字、重复画面或极端变速。
- EDGE-004：人脸持续过小、严重侧脸/背脸、遮挡、运动模糊、快速出画或身份跟踪置信不足时，保留原帧并报告区间；不得改用全脸生成或错误人物。
- EDGE-005：任何 renderer 传入的路径、ID、枚举、数值、URL、发布字段和任务操作都按不可信输入处理；拒绝越界路径、未知平台/域名、非法状态转换和非授权窗口调用。
- EDGE-006：同一 GPU 上的 IndexTTS 与 MuseTalk 在低显存模式串行加载；OOM 不无限降低质量或循环重试，释放资源并给出可选择的兼容模式或失败结果。
- EDGE-007：模型、ASR、工具或浏览器资源下载中断、校验失败、版本不匹配、许可证信息缺失、解压路径越界或磁盘不足时不标记为可用，不执行损坏资源；重试只复用仍满足固定版本和哈希的已完成分项。
- EDGE-008：Worker 无响应、退出、协议版本不匹配、返回畸形消息或无法取消时，主进程终止受控进程、清理监听和句柄，并将任务置为可解释终态。
- EDGE-009：取消、应用退出或窗口销毁不会继续向已销毁 renderer 发送事件；不会删除源文件或已确认音色；中间目录按状态恢复或安全清理。
- EDGE-010：发布页面不在白名单域名、页面结构/字段不匹配、上传失败、验证码/扫码/风控出现或提交状态不确定时停止；提交按钮不得在一次用户操作中被重复点击。
- EDGE-011：发布成功只代表平台接收提交；除非页面明确返回审核状态，否则不得显示审核通过；状态不确定时不得自动重发。
- EDGE-012：平台发布资料始终绑定页面当前选择的生成任务、受管视频路径和文件内容指纹；切换历史/当前视频、封面或平台后旧确认失效，防止预览与实际发布内容错配。
- EDGE-013：删除音色时同时删除受管参考音频、转写和派生特征；被运行中任务引用时拒绝删除，失败时报告未删除项而不产生假成功。
- EDGE-014：日志、异常和测试 fixture 不包含完整文案、音色参考、视频内容、浏览器凭据、OAuth/会话值或可还原生物特征。
- EDGE-015：统一页面中的长任务、菜单切换和历史视频切换必须保持请求代次与进行中锁定；迟到响应不得覆盖较新的音色、文案、视频、平台或草稿选择，发布请求执行期间冻结参与本次提交的输入。

### 非功能需求（NFR-*）

- NFR-001：首版完整推理目标平台为 Windows 11 x64 + NVIDIA CUDA；4GB 为兼容模式、6GB 为最低建议、8～12GB 为推荐，不宣称未验证平台等价。
- NFR-002：在模型已安装和热启动、单人物、1 分钟 1080p 25/30fps 合格素材上，RTX 3060 Laptop 6GB 的目标端到端生成时间不超过 8 分钟；该目标必须以真实硬件证据决定是否达成。
- NFR-003：除嘴部及自然融合所需最小邻域外，输出画面不得出现可感知的主动修改；速度优化不得降低输出规格、扩大蒙版或跳过质量门禁。
- NFR-004：合格坐姿与正常走动素材均需达到可发布的身份稳定、无明显贴片边缘、无明显嘴部漂移/闪烁和可接受音画同步；“自然”不对不合格输入做无条件保证。
- NFR-005：媒体内容通过受控路径和只读媒体协议流处理，不通过 Electron IPC Buffer 传输；内嵌视频预览不得向 renderer 暴露任意文件路径，长任务不得阻塞 renderer 或 Electron main 事件循环。
- NFR-006：AI 推理仅在独立 Worker 中执行；协议、模型适配器和平台适配器可独立替换，业务模块不依赖第三方仓库内部布局或网页选择器细节。
- NFR-007：默认无按次付费 API；除模型/工具首次下载和用户明确的平台发布外，核心生成不需要外网。
- NFR-008：任务、文件和发布状态持久化具有原子性；崩溃、取消、磁盘不足和重启不会覆盖源素材或把半成品标成成功。
- NFR-009：用户数据、模型许可、平台登录和发布行为满足 AGENTS 与 PRD 的安全合规边界；外部写入必须可审计但日志不含敏感内容。
- NFR-010：新模块均有职责 README、最小公共类型与 IPC，稳定业务规则具备风险驱动自动化测试；硬件、模型质量和真实平台行为具备明确真实验收记录。

## 7. 数据与状态生命周期

- 受管根目录：由 main 基于 Electron `app.getPath('userData')` 解析，业务模块不能接受 renderer 指定的任意存储根。建议分为 `models/`、`voices/`、`jobs/`、`outputs/`、`cache/`、`browser/` 和 `runtime/`；最终物理命名在 Plan 中确定，但职责不得跨模块混用。
- 音色：以不可猜测 ID 标识；元数据包含显示名、创建/更新时间、模型及协议版本、参考媒体指纹、受管参考音频/转写/特征路径和试听状态。创建采用临时目录后原子提交；更新成功后替换，失败保留旧版本；删除遵循 EDGE-013。
- 生成任务：包含任务 ID、A 视频内容指纹、音色版本、文案摘要而非完整日志、语气/语速、音轨策略、目标人物、各阶段状态、进度、检查点、输出及质量报告。任务状态机至少覆盖 queued、running、waiting-user、cancelling、cancelled、failed、completed。
- 音频：文案分段产物进入任务私有临时目录；只有通过内容/完整性检查并经用户确认的音频成为后续输入。文案或音色版本变化使旧音频确认失效。
- 视频：源 A/B 文件只读，不移动、不覆盖；输出写入受管输出或用户通过保存对话框明确选择的新路径。成功任务索引保存预览所需的受管输出相对路径和内容指纹；历史列表读取时复验文件，失效记录不作为可发布视频。临时帧、裁剪和缓存按任务隔离。
- 跟踪缓存：键由 A 视频内容指纹、跟踪器版本及参数共同决定；任一变化使缓存失效。缓存只含必要坐标/特征，不保存额外完整视频副本。
- 发布草稿：绑定任务 ID、输出文件指纹、平台、文案、封面和确认版本；任一内容改变后发布确认失效。提交中状态持久化，重启后进入“状态不确定/待核对”而非自动重试。
- 浏览器资料：抖音与小红书分目录保存，仅平台适配器可访问；退出登录/清除平台数据由用户显式触发。不得复制日常浏览器 profile。
- store：只保存经过 schema 校验的索引、状态和设置，不保存媒体 Buffer、登录 secret 或可还原音色特征正文；大文件使用受管文件系统。
- 兼容：本项目默认不为未发布旧结构设计迁移。模型/协议版本变化必须拒绝不兼容档案或通过未来 Spec 定义升级，不静默猜测。

## 8. Electron 系统影响

- renderer UI/路由：保留“视频音色”“生成视频”“发布视频”和“本地推理”四个业务菜单，全部复用原系统 `SettingLayout` 并装配到 `config/menus.tsx`；不新增独立工作台或第二套配置窗口。“视频音色”页面只展示 B 视频授权选择及音色创建/更新；“生成视频”页面组合 voice/video 的最小 preload 公共面，先展示音色库、文案和音频试听，再展示视频质检/生成与当前结果预览；“发布视频”页面展示历史/当前视频选择及预览、封面、发布文案、平台选择和发布确认。renderer 不接触 Node、真实文件路径、模型或浏览器凭据。
- main 业务与生命周期：四模块 main 入口按依赖顺序装配；inference 管理 Worker/工具/任务，voice/video/publish 各自校验业务状态；应用退出时停止任务、关闭 Worker 与受管浏览器，并持久化非成功终态。
- preload/IPC/公共类型：每个业务模块仅暴露所需命令与订阅；使用集中 channel 常量、带判别字段的结果、显式 operation 权限和严格参数解析；事件监听返回取消函数并在 webContents 销毁时清理。
- store、文件、网络：main 负责真实路径规范化、文件类型/大小/指纹、受管目录和原子写入；网络仅用于受控资源下载和用户触发的平台页面，域名有白名单；不暴露通用文件、命令或网络 IPC。
- 权限、硬件、原生能力：Windows 检测 NVIDIA/CUDA/编码器；Worker、FFmpeg 和浏览器均为受控子进程或运行资源。首版不新增摄像头、麦克风、辅助功能或全局 Hook 权限。
- `config/` 装配：按需更新 `config/main.ts`、`config/preload.shared.ts`/`config/preload.ts`、`config/routes.ts`、`config/window.ts`、`config/menus.tsx` 与 `config/dock.ts`；删除 `talkHero` 窗口声明，原 `setting` 窗口负责首次启动、Dock 激活、系统配置及全部业务页面。增加只承载创建/更新的 voice 配置路由，把 voice 音频内容组合进 video 生成路由，并恢复独立 publish 配置路由；不得新建第二套设置布局或跨模块搬迁 main 业务。
- 构建、签名、更新：需要验证新 JavaScript 依赖和 Worker 启动路径可被 electron-vite/electron-builder 正确处理，但模型、运行环境和下载资源不直接提交到安装包；本 Spec 不修改签名、公证、更新源或正式发布流程。

## 9. 平台兼容

- macOS 15+ Apple Silicon：桌面 UI、纯业务规则、类型和构建不得被无谓破坏；完整 IndexTTS/MuseTalk 推理与平台自动发布不属于首版验收，不显示为已支持能力。当前 macOS 可用于 Mock/契约验证，不能替代 Windows 真实证据。
- Windows 11 x64：首版完整目标平台；需在 NVIDIA 4GB 兼容档和至少 RTX 3060 Laptop 6GB 建议档验证环境安装、音色、坐姿/走动口型、取消/OOM恢复、硬件编码和打包后路径。
- Linux：明确不支持；不得因 Python/模型自身支持 Linux 而对外开放未验证入口。

## 11. 功能阶段（What）

### 阶段 1：本地运行底座与统一系统界面

- 用户可观察目标：能够打开原系统 `setting` 窗口，在“本地推理”中一键自动安装应用受管资源，并通过“视频音色”“生成视频”“发布视频”三个分工明确的页面完成音色、音频、视频预览、历史结果与发布流程，观察任务进度与错误。
- 覆盖编号：FR-001、FR-002、FR-009、EDGE-005～EDGE-009、NFR-001、NFR-005～NFR-010。
- 不包含：真实音色、口型和平台提交结果。
- 完成定义：四模块骨架和装配成立；环境、协议、资源与任务状态机可测试；Windows 真实环境能启动受管 Worker 并报告可信状态。

### 阶段 2：音色档案与文案音频

- 用户可观察目标：在“视频音色”页面用合格 B 视频创建或更新可复用音色，再在“生成视频”页面选择音色与独立文案生成、试听和确认音频。
- 覆盖编号：FR-003～FR-005、FR-014～FR-015、EDGE-001、EDGE-003、EDGE-006～EDGE-009、EDGE-013～EDGE-014、NFR-005～NFR-010。
- 不包含：改变 A 视频或发布网站。
- 完成定义：B 视频不再被后续要求；音色 CRUD、分段 TTS、失败恢复、隐私删除和真实 Windows 音色盲听/文案正确性有证据。

### 阶段 3：A 视频局部口型

- 用户可观察目标：在“生成视频”页面选择 A 视频和已确认音频，对坐姿或正常走动人物只改变嘴部并生成原规格新视频；完成后自动选中并以内嵌播放器预览。
- 覆盖编号：FR-006～FR-009、FR-014～FR-015、EDGE-002～EDGE-009、EDGE-014、NFR-001～NFR-010。
- 不包含：512 高清模式、全脸处理和平台发布。
- 完成定义：质检、人物锁定、256 局部推理、蒙版融合、音轨策略、缓存/取消/失败片段均可观察；Windows 3060 真实素材完成质量和性能验收。

### 阶段 4：封面、文案与双平台发布

- 用户可观察目标：在“发布视频”页面选择并预览当前或历史生成视频，获得 3 张封面和可编辑发布文案，选择抖音或小红书，并在明确点击后自动完成对应网页上传、填表和提交。
- 覆盖编号：FR-010～FR-015、EDGE-005、EDGE-009～EDGE-012、EDGE-014、NFR-005～NFR-010。
- 不包含：绕过验证、后台静默/定时发布和平台审核保证。
- 完成定义：封面/文案与任务绑定；两个平台适配器可暂停恢复且防止重复提交；至少完成不产生公开内容的真实网页填表验收，实际提交仅在用户另行明确授权的测试内容上验证，否则必须标为未执行。

## 13. 验收标准（AC-*）

### AC-001：环境检测与受管资源

- 关联需求：FR-001、FR-002、EDGE-005～EDGE-008、NFR-001、NFR-005～NFR-009。
- 前置条件：Windows NVIDIA 环境分别处于资源完整、资源缺失、校验失败和磁盘不足状态。
- 操作：打开原系统 `setting` 窗口的“本地推理”菜单，查看预计下载量/磁盘/许可证后点击一次“安装所需资源”，并分别执行取消、断网重试和损坏修复。
- 可观察预期：一次点击后无需命令行或逐项手工安装即可自动完成全部应用受管资源；UI 显示真实平台/GPU/显存、总进度和分项状态；只执行固定来源且逐项校验通过的资源；失败进入可解释终态并可复用合格分项；系统级 NVIDIA 驱动只给出引导；renderer 不能指定命令、下载域名或任意安装路径。

### AC-002：从 B 视频创建可复用音色

- 关联需求：FR-003～FR-004、FR-014～FR-015、EDGE-001、EDGE-005、EDGE-013～EDGE-014、NFR-007～NFR-010。
- 前置条件：准备获授权的合格 20 秒单人 B 视频及无音轨、超时长、多人/噪声不可用样本。
- 操作：进入独立“视频音色”菜单，确认授权，创建、试听、命名音色；随后关闭应用并重新打开；再更新和删除音色。
- 可观察预期：“视频音色”页面只承载创建或更新音色所需的授权素材选择、名称和操作，不出现文案音频制作；合格样本生成可试听且重启后可用的音色档案；后续不要求 B 视频；非法样本不创建可用档案；更新失败保留旧音色；删除清除受管参考及特征且不泄露敏感日志。

### AC-003：独立文案生成正确音频

- 关联需求：FR-005、FR-009、EDGE-003、EDGE-006～EDGE-009、NFR-004～NFR-008。
- 前置条件：已有音色档案，准备短文案、接近 3 分钟的中文文案、多音字/数字/标点样本和不合理时长样本。
- 操作：选择语气/语速生成、试听、确认、取消并重试。
- 可观察预期：音频内容只来自文案，无可感知漏读、重复或凭空添加；长文案分段衔接自然；不合理时长不静默改写；取消和失败不产生已确认音频；同一音色持续保持可识别的一致音色。

### AC-004：A 视频质检与人物锁定

- 关联需求：FR-006、EDGE-002、EDGE-004～EDGE-005、NFR-003～NFR-005。
- 前置条件：准备坐姿、正常走动、多人、遮挡、侧脸、远景、模糊、无脸、损坏和超过 3 分钟的视频。
- 操作：依次上传并查看质检、选择人物和可用时段。
- 可观察预期：系统报告媒体与人脸风险；多人必须人工选定；身份不会切换；不可用输入被拒绝或明确警告，原文件不改变。

### AC-005：只改变嘴部并正确对口型

- 关联需求：FR-007～FR-009、EDGE-004、EDGE-006、NFR-003～NFR-005。
- 前置条件：获授权的合格坐姿和正常走动 A 视频，以及 AC-003 确认音频。
- 操作：在“生成视频”页面分别生成并以内嵌播放器预览结果，再对比源视频与结果视频。
- 可观察预期：生成成功后结果自动选中且可在软件内播放/暂停/拖动预览；口型与音频可接受同步；目标人物身份稳定；除嘴部及必要最小融合区外没有可感知主动修改；背景、身体、动作、画幅、分辨率、帧率和时长保持；遮挡/丢失帧保留原画并出现在质量报告。

### AC-006：音轨策略和源文件保护

- 关联需求：FR-008、FR-015、EDGE-005、EDGE-009、NFR-003、NFR-005、NFR-008。
- 前置条件：分别准备有环境声和无声 A 视频。
- 操作：选择混音或替换策略生成，并尝试非法输出路径和取消。
- 可观察预期：结果音轨符合明确选择；源文件字节和路径不变；输出为新文件；非法路径被拒绝；取消不会覆盖源/已有结果。

### AC-007：任务进度、缓存、取消与故障恢复

- 关联需求：FR-002、FR-009、EDGE-006～EDGE-009、NFR-002、NFR-005、NFR-008。
- 前置条件：可控制 Worker 延迟、崩溃、OOM、畸形消息、磁盘不足和应用重启；同一 A 视频可重复提交。
- 操作：运行、取消、故障注入、重启和重复生成。
- 可观察预期：状态转换合法且 UI 不假死；资源最终释放；不把半成品标记成功；输入一致时复用缓存，输入变化时缓存失效；重启后提交中/运行中任务进入安全可恢复状态。

### AC-008：封面与发布文案

- 关联需求：FR-010、FR-015、EDGE-012、EDGE-014、NFR-003、NFR-007～NFR-010。
- 前置条件：已有生成视频和确认文案，视频包含清晰/模糊、有人脸/无人脸候选帧。
- 操作：在“发布视频”页面从历史结果中选择视频并预览，生成标题、简介、话题和封面，编辑其中一项后再切换视频。
- 可观察预期：历史列表只允许选择仍存在且通过任务/路径/指纹复验的视频；生成 3 张独立封面并推荐清晰、避让人脸的一张；文本可编辑且不生成明显无关话题；封面不修改视频；切换视频使旧确认失效且预览、草稿和发布资料绑定同一内容指纹。

### AC-009：抖音网页一键发布

- 关联需求：FR-011～FR-015、EDGE-005、EDGE-010～EDGE-012、EDGE-014、NFR-006～NFR-010。
- 前置条件：用户明确授权的抖音测试账号/内容，或在无提交权限时采用停止在最终提交前的真实页面验收；准备登录、未登录和页面不匹配状态。
- 操作：在“发布视频”页面选择历史/当前视频和抖音，预览资料并点击抖音“一键发布”，处理可能的扫码/验证码，再观察提交状态。
- 可观察预期：只打开白名单官方域名；正确上传当前视频/封面并填写当前表单；只有本次明确点击可触发一次提交；人工验证时暂停；页面不匹配或结果不确定时不重复提交、不误报成功。

### AC-010：小红书网页一键发布

- 关联需求：FR-011～FR-015、EDGE-005、EDGE-010～EDGE-012、EDGE-014、NFR-006～NFR-010。
- 前置条件：用户明确授权的小红书测试账号/内容，或在无提交权限时采用停止在最终提交前的真实页面验收；准备登录、未登录和页面不匹配状态。
- 操作：在“发布视频”页面选择历史/当前视频和小红书，预览资料并点击小红书“一键发布”，处理可能的扫码/验证码，再观察提交状态。
- 可观察预期：只打开白名单官方域名；正确上传当前视频/封面并填写当前表单；只有本次明确点击可触发一次提交；人工验证时暂停；页面不匹配或结果不确定时不重复提交、不误报成功。

### AC-011：性能与低显存调度

- 关联需求：FR-002、FR-007、FR-009、EDGE-006、NFR-001～NFR-002、NFR-005。
- 前置条件：模型热启动，准备 1 分钟 1080p 25/30fps 合格单人素材；分别使用 RTX 3060 Laptop 6GB 和可获得的 4GB Windows NVIDIA 设备。
- 操作：完成音频和视频生成并记录阶段耗时、峰值显存和结果。
- 可观察预期：6GB 环境目标不超过 8 分钟；IndexTTS 与 MuseTalk 不同时驻留导致 OOM；4GB 能进入兼容模式或给出明确不支持原因，不虚报性能；结果仍满足 AC-005。

### AC-012：打包、退出与敏感信息边界

- 关联需求：FR-001～FR-015、EDGE-005、EDGE-008～EDGE-009、EDGE-014、NFR-005～NFR-010。
- 前置条件：Windows 打包产物、运行中任务和已登录的受管平台会话。
- 操作：安装/启动应用、运行任务、关闭窗口/退出应用并检查日志、进程、受管目录和安装包内容。
- 可观察预期：模块、Worker 和工具路径在打包环境可解析；退出后无孤儿 Worker/浏览器；安装包不含模型权重、个人素材、登录资料或签名秘密；日志无敏感正文；现有 auth/core 基础能力未被破坏。

### AC-013：三个配置页面的流程一致性

- 关联需求：FR-001、FR-003～FR-013、EDGE-005、EDGE-009、EDGE-012、EDGE-015、NFR-005～NFR-010。
- 前置条件：已有至少一个音色、一个确认音频、一个正在生成的视频任务和两个历史成功视频；可控制异步任务延迟。
- 操作：在“视频音色”创建或更新音色；进入“生成视频”，确认“音色库与文案音频”和 A 视频对口型位于同页并依次完成音频、视频和当前结果预览；再进入“发布视频”选择当前或历史结果、预览、生成发布资料并选择平台。长任务期间切换系统菜单后返回并尝试修改或重复操作。
- 可观察预期：三个页面分别承担音色配置、音频与视频生成、视频发布，页面间不重复整块功能；当前步骤、结果、错误、共享文案和进行中锁定跨菜单保持；迟到响应不得覆盖较新选择；生成结果、发布页预览、草稿、封面、平台确认和最终发布始终绑定同一任务与内容指纹。

## 16. 发布、兼容与恢复

- 现有用户/数据：新增模块使用独立 store 与受管目录，不迁移或重写 core/auth/secret 数据；原 `setting`、login、pay 窗口和认证能力保持可用，未发布的独立 `talkHero` 窗口定义直接移除且不提供兼容入口。

- 模型/工具：首次下载可取消和重试，只有哈希与版本通过后原子标记可用；损坏或不兼容资源隔离，不删除用户源媒体。
- 任务恢复：源文件永不覆盖；中间产物按任务隔离；崩溃/退出后非成功任务恢复为安全状态，由用户选择继续、重试或删除。
