## 1. 背景与目标

- 当前问题：feature worktree 已完成本地任务/资源、音色档案、媒体质检、生成历史、发布草稿和基础界面契约，但真实模型资源清单、跨平台 Worker、主体身份跟踪、MuseTalk 局部生成/合成、质量报告和平台网页发布尚未形成可交付闭环；当前实现仍不能生成可发布的对口型视频。
- 目标用户：拥有本人或已取得单独授权的人脸与人声素材，希望在本机快速制作 3 分钟以内口播短视频并发布到抖音、小红书的创作者。
- 功能目标：用户可在软件内一键安装全部应用受管资源；在独立“视频音色”页面从 B 视频创建或更新音色，在“生成视频”页面依次使用音色库与文案音频并处理 A 视频，在独立“发布视频”页面选择及预览当前或历史结果、生成发布资料；由用户明确点击抖音或小红书后自动完成对应平台网页上传、填表和提交。
- 总体完成定义：四个新模块按约定装配；核心流程、失败与恢复状态可观察；Electron 只承担跨平台 UI 与受控编排，默认模型为 CosyVoice2 0.5B 与 MuseTalk 1.5；合格素材能在 Windows NVIDIA、Windows Core Ultra X9 388H/X7 358H 集成 Arc B390 和 macOS Apple Silicon 的独立本地 Worker 后端完成端到端生成并满足同一自然度与嘴部最小修改门禁；抖音、小红书发布适配器能在不绕过登录、标识或风控的前提下执行；自动化、类型、lint、构建、目标平台真实运行和独立审查达到本 Spec 的交付门禁，或对缺失硬件证据明确披露而不虚报正式支持。

## 2. 模块归属

- 类型：新模块、跨模块功能。
- 目标 `apps/<module>` 或业务域：
  - `apps/inference`：本地 Python Worker、模型与媒体工具、硬件检测、资源调度及任务协议。
  - `apps/voice`：B 视频预处理、音色档案生命周期、文案转音频与试听。
  - `apps/video`：A 视频主体人物确认、身份跟踪、口型、局部融合和视频输出。
  - `apps/publish`：标题、简介、话题、封面和抖音/小红书网页发布。
- 判断依据与相邻边界：`apps/core` 继续只提供窗口、store、系统和共享 Electron 基础设施；`apps/auth` 的登录与订阅语义不变；AI 模型和 FFmpeg 不进入 Electron renderer/main 的执行上下文；ASR、FFmpeg、封面以及单个平台只是上述模块内部适配器，不新增 app。

## 3. 范围与非范围

### 范围内

- Windows 11 x64 + NVIDIA CUDA、Windows 11 x64 + Intel Core Ultra X9 388H/X7 358H 集成 Arc B390、macOS 15+ Apple Silicon M1 及以上的环境检测、平台专用受管 Python Worker、模型/工具安装状态与任务资源调度。NVIDIA 正式档最低 8GB 显存与 16GB 系统内存；Arc B390 使用共享内存，首版正式档最低 32GB 系统内存；Apple Silicon 最低 16GB 统一内存。不得把所有 Core Ultra Series 3 或所有 Intel 集显自动视为同等支持，后续只能依据真机证据下调门槛。
- Electron renderer/main 只负责 UI、受控文件访问和任务编排；AI、视频逐帧处理和 FFmpeg 始终在独立 Worker/受管进程中执行。按检测结果只安装 `windows-cuda`、`windows-xpu` 或 `macos-mps` 中一个平台运行包，共享业务协议、模型版本、质量规则与输出契约。
- 在“本地推理”页由用户点击一次“安装所需资源”后，软件自动按平台固定清单下载、校验并原子安装受管 Python 3.11、对应 PyTorch/加速后端、模型权重、ASR、FFmpeg/ffprobe 与受管浏览器；显示总量、磁盘需求、许可证入口、分项进度、取消、重试与修复。NVIDIA/Intel 驱动和 macOS 等系统级前置条件只检测和引导，不静默安装或修改系统 Python。
- 从 10～60 秒且只有一个有效说话人的 B 视频创建本地音色档案，推荐 15～30 秒；自动提取音轨、筛选有效单人语音、基础清理、自动转写、试听和保存。画面中可出现其他静默人物，但不得让其他人的声音进入参考音频。
- 音色档案的列表、试听、重命名、更新与删除；同一音色在后续任务中复用且不要求再次上传 B 视频。
- 使用 CosyVoice2 0.5B 从已保存音色和独立文案生成音频，首版保证自然语音、合理语速控制、分段生成、试听与保存；热情、沉稳、讲解等语气只有在固定版本真实盲听证明稳定且不损害音色相似度、读音和跨平台一致性后才开放，不把上游存在参数等同于产品能力。
- 对不超过 3 分钟的 A 视频执行媒体校验、人脸质量检查与主体人物身份锁定；每个任务只处理一个主体人物的口型，允许其他人物在背景、路过或其他镜头中出现。系统默认识别并展示主体，存在多个合理候选时由用户确认一次；支持主体坐姿、站立和正常走动。
- 首版 A 视频输入限 MP4/MOV 容器、H.264/H.265 8-bit SDR、恒定 24/25/30fps，最大 1080p（横屏 1920×1080、竖屏 1080×1920 及不超过该像素量的其他比例）；输出统一为兼容平台上传的 MP4 H.264/AAC，并保持输入画幅、像素尺寸、帧率与时长。VFR、HDR/Dolby Vision、10-bit、4K、损坏时间戳和其他容器/编码不在首版正式支持范围，不静默转色或降分辨率。
- 使用 MuseTalk 1.5 的 256×256 内部人脸工作区生成口型，只融合嘴部及自然过渡所需的最小邻域；输出保持输入画幅、像素尺寸、帧率与时长，但按首版媒体矩阵重新编码为 MP4 H.264/AAC，不承诺保留源容器、编码器或码率。
- 在独立“视频音色”页面完成音色创建、更新及授权素材选择；在“生成视频”页面先完成音色库/文案音频，再完成 A 视频对口型和当前结果预览；在独立“发布视频”页面完成历史/当前生成视频选择与预览、发布资料编辑和平台发布。
- 视频生成成功后自动选中并在页面内预览；历史列表只展示任务记录中已完成且受管输出仍存在并通过指纹复验的视频，缺失或损坏项显式不可用。
- 默认以新语音替换 A 视频原音轨。只有质检确认所选原音轨不含可辨识前景人声时，才允许“保留环境声并混合新语音”；原音轨存在人物讲话、无法可靠判断或会形成双重人声时禁用混音并提示改用替换。首版不以未验证的人声分离模型承诺保留含原说话声的环境音；选择必须显式，不覆盖源文件。
- 生成任务的排队、进度、取消、阶段检查点、有限重试、失败片段报告和同一 A 视频跟踪缓存复用。
- 完整生成前默认提供同一参数下 5～10 秒的用户试生成：优先选择包含说话、运动或转头的代表性区间，允许用户改选区间、确认后继续或显式跳过；试生成不降低最终模型、嘴部工作区或质量门禁。生成后以时间轴列出需复核片段并可直接循环预览。
- 首版提供完全本地的基础字幕：以用户确认的原文为字幕正文，以最终生成音频为时间基准，使用固定版本的 `faster-whisper` 取得本地时间锚点并把原文对齐为可编辑字幕；支持 UTF-8 SRT 导出。用户可明确选择额外生成带字幕的发布副本，系统始终保留不含字幕的干净口型结果；字幕不参与或改变口型推理。
- 保持模型权重、256×256 嘴部工作区、输出规格和质量门禁不变的性能优化：批量推理、平台 FP16/BF16、固定形状编译、硬件解码/编码、避免逐帧图片落盘，以及复用人脸坐标、身份、蒙版和 VAE latent；不得以跳帧、补帧、降低嘴部工作区分辨率、INT4 或扩大整脸生成换取速度。
- 根据文案生成可编辑的标题、简介和相关话题；从视频抽帧并使用本地模板生成 3 张候选封面，自动推荐 1 张。
- 使用应用受管的独立浏览器资料目录，分别适配抖音和小红书创作者页面；用户明确触发后自动打开页面、上传视频与封面、填写表单并点击提交。
- 登录、扫码、验证码、风控和状态不确定时暂停或失败，不绕过平台控制；仅在页面给出可验证成功状态时报告提交成功。
- 人脸、人声授权确认、AI 内容声明入口、本地隐私、敏感日志过滤与受管数据删除。
- 商业交付前完成模型、权重、字体、浏览器、FFmpeg 与全部传递依赖的许可证物料清单、NOTICE/协议展示和分发边界审计。生产资源只允许采用许可证文本本身明确允许本产品商用、修改和所需分发方式的版本；不得把“等待权利方回复”“另行申请授权”或仓库可下载作为交付前提，任何非商用、自定义限制不清或缺少许可证链的必需项直接淘汰或更换。这里的“免费”指不支付模型/API 授权费，不代表资源托管、下载带宽、代码签名和测试硬件没有成本。

- 四个新模块的 README、最小 preload/IPC 公共类型、主窗口/路由和必要 `config/` 装配。

## 5. 目标行为与流程

### 主流程

1. 前置条件：用户进入原系统 `setting` 窗口的“本地推理”菜单；操作：查看检测结果并点击“安装所需资源”；状态变化：软件识别 Windows CUDA、Windows XPU 或 macOS MPS 能力和内存、驱动、磁盘、已有资源，只选择一个匹配的平台运行包并按受信清单下载、校验和原子安装；可观察结果：明确显示实际设备后端、安装总量、分项进度、当前阶段、取消、失败原因、重试和修复。系统级驱动或 OS 不满足时停止并给出人工处理指引。
2. 前置条件：环境可支持音色创建；操作：用户进入原系统 `setting` 窗口的独立“视频音色”菜单，确认拥有授权并选择 B 视频；状态变化：受控路径经 main 校验后进入 voice 任务；可观察结果：显示媒体/人声质检、转写、试听和可命名音色档案，并可在该页更新已有音色参考。
3. 前置条件：已有音色；操作：用户进入“生成视频”页面，在“音色库与文案音频”区域选择音色、输入文案并设置语速；状态变化：voice 调用 inference 分段生成自然语音；可观察结果：用户能试听、重做或确认音频，B 视频无需再次提供。只有已通过质量门禁的附加语气才显示可选项。
4. 前置条件：音频已确认；操作：用户在同一个“生成视频”页面继续选择 A 视频和音轨处理方式，并在有多个合理人物候选时确认主体；状态变化：video 锁定该主体身份并完成人物跟踪、局部口型、融合、音频合成和输出，同时用原文与最终音频在本地生成可编辑字幕草稿；可观察结果：用户获得不覆盖源文件、保持画幅/像素尺寸/帧率/时长且符合首版输出矩阵的视频，生成成功后自动选中并在页面内播放预览，同时能看到进度、失败片段和字幕时间轴，可导出 SRT 或明确选择生成独立的带字幕发布副本。
5. 前置条件：至少存在一个成功生成的视频；操作：用户进入独立“发布视频”页面选择刚生成或历史生成视频；状态变化：系统复验完成任务、受管路径和文件指纹，publish 为所选视频生成并保存可编辑文案及 3 张封面；可观察结果：视频预览、推荐封面和所有将提交的字段属于同一个已校验视频。
6. 前置条件：发布资料已确认；操作：用户仍在“发布视频”页面选择抖音或小红书并点击对应“一键发布”；状态变化：平台适配器启动/复用独立浏览器会话并执行上传、填表和提交；可观察结果：显示等待登录/人工验证、提交成功、失败或状态不确定，不把提交成功误报为审核通过。

### 关键失败流程

- 环境、模型、工具或磁盘不满足要求时阻止对应任务，显示缺失项与可恢复操作，不进入无意义重试。
- Windows 10、Windows ARM、Intel Mac、低于对应平台内存/显存门槛、无受支持 GPU 后端或平台算子不完整时，不回退到不可预测的长时间纯 CPU 视频生成；界面保留可安全使用的非视频能力并明确说明限制。
- 一键安装中任一资源下载中断、哈希不符、许可证信息缺失、解压越界或磁盘不足时停止在明确分项，未校验资源不得进入可用目录；已完成且仍通过校验的分项可在重试时复用。
- B 视频无音轨、超出时长、出现第二个有效说话人、没有足够清晰的主体语音或转写失败时不创建音色档案，不保留半成品为可用音色；仅有其他静默人物入镜不构成拒绝原因。
- 文案为空、超过可处理上限、生成内容与文案不一致或音频时长无法在合理语速内适配 A 视频时，阻止口型任务并允许修改文案/语速或重新生成。
- 字幕时间锚点缺失、顺序冲突、越出最终音频时长或置信不足时，不擅自改写原文；标出待校正区间并要求用户编辑/确认。未确认字幕不得烧录或随平台任务提交，但不阻止用户使用无字幕的干净口型结果。
- A 视频超时长、格式不支持、无法可靠建立或确认主体身份，或主体可用人脸时段不足时，不启动口型并明确原因。其他人物出现时不拒绝任务，但不得把处理身份切换给其他人物；主体暂时丢失时保留原帧并报告区间。
- 运行中跟踪丢失、遮挡、严重侧脸或模糊时，不扩大生成区域；保留原帧并记录失败片段，最终结果必须带质量警告或阻止“合格”状态。
- Worker 崩溃、OOM、模型损坏、工具失败、取消或磁盘不足时，任务进入明确终态，释放资源并保留可复用的已完成阶段。
- 发布遇到未登录、验证码、扫码、风控或平台确认时暂停等待用户；DOM/URL 不匹配、上传失败或提交结果不确定时停止，不自动重复点击提交。
- 历史视频记录对应文件缺失、损坏、越出受管输出目录或指纹不符时禁止预览与发布，并提供重新生成或移除失效记录的明确操作。

### 恢复流程

- 环境安装失败可从已校验下载点重试；损坏资源先隔离再重新下载，不复用未校验文件。
- 音色创建失败可更换 B 视频；成功音色不因后续音频/视频任务失败而损坏。
- 生成任务按阶段保存检查点；重试从最后一个完整且输入指纹一致的阶段开始，输入变化后旧检查点失效。
- 取消向 Worker 发送受控取消并在超时后终止该任务进程；UI 等待主进程确认终态，不伪造即时取消成功。
- 发布暂停后只能由用户对同一任务点击继续；状态不确定的任务要求用户先核对平台作品列表，软件不自动重发。

## 6. 需求清单

### 功能需求（FR-*）

- FR-001：不新增或保留独立 TalkHero 工作台窗口；原系统 `setting` 窗口作为唯一主界面，继续使用既有 `SettingLayout`。业务菜单为“视频音色”“生成视频”“发布视频”和“本地推理”，并保留原有“帐号订阅”“更新软件”“系统配置”。“视频音色”只承载创建或更新音色；“生成视频”承载音色库/文案音频和 A 视频对口型；“发布视频”承载历史/当前视频选择、预览、发布资料与双平台发布。
- FR-002：`apps/inference` 通过有版本的结构化协议管理独立 Python Worker，探测 Windows 11 x64 NVIDIA CUDA、Windows 11 x64 Core Ultra X9 388H/X7 358H 集成 Arc B390 的 XPU/OpenVINO 后端，或 macOS 15+ Apple Silicon MPS/Core ML，以及内存、驱动、磁盘、模型、ASR、FFmpeg 与浏览器资源；用户点击一次“安装所需资源”后，软件只安装匹配平台的固定清单，逐项哈希校验、原子安装和可用性复检，并提供总量、分项状态、进度、取消、错误、重试和修复。不得只凭 CPU/系统名称放行，必须执行实际设备、内存、驱动、模型加载和关键算子探针；不得自动安装系统驱动、修改系统 Python、混装互斥后端或执行清单外安装命令。
- FR-003：用户确认人脸与人声授权后，可从 10～60 秒且只有一个有效说话人的 B 视频创建音色；系统验证单说话人，提取和清理主体语音、自动转写、生成试听并保存命名档案。其他静默人物可出现在画面中，但其声音不得混入参考音频。
- FR-004：音色库支持列表、试听、重命名、更新和删除；后续生成从档案读取参考音频、转写和特征，不再要求 B 视频。
- FR-005：用户选择音色、输入独立文案和合理语速后，CosyVoice2 0.5B 分段生成内容严格来自文案的可试听音频；确认的音频可被保存和复用。首版默认自然语音，其他语气只有在固定资源与三平台质量门禁通过后才显示。
- FR-006：用户上传不超过 3 分钟的 A 视频后，系统显示格式、时长、画幅、帧率、人脸大小/清晰度/角度/遮挡/出画/模糊质检，并基于持续出现时间、画面占比和身份连续性提出一个主体候选。只有一个明确候选时展示主体缩略图供用户核对；多个候选接近时要求用户确认一次。其他人物不参与口型生成。
- FR-007：MuseTalk 1.5 以 256×256 内部人脸区域驱动口型，在各平台后端使用相同模型版本、主体身份锁定、跨帧跟踪、时序稳定和嘴部蒙版规则处理主体坐姿、站立或正常走动，并只将主体嘴部及必要最小过渡区融合回原始帧；其他人物的脸和嘴必须保持原画。主体严重侧脸、遮挡、模糊、出画或跟踪置信不足时保留原帧并按失败片段处理，绝不切换到其他身份。
- FR-008：默认使用新语音替换 A 视频原音轨；仅当质检确认原音轨没有可辨识前景人声时开放“保留环境声并混音”。存在或无法排除原说话声时不得简单叠加新旧音轨。新音频短于视频时以静音补齐并继续让主体嘴部保持与静音一致的自然静止状态；新音频长于视频时只允许在已批准自然语速范围内重新生成，仍超长则拒绝，不裁字、不截音频、不延长或循环画面。输出写入新文件并满足首版媒体矩阵，不执行其他画面处理。
- FR-009：生成任务显示阶段、基于已完成阶段和本机实测吞吐估算的剩余时间范围、取消、失败原因与失败片段；同一 A 视频输入指纹一致时可复用人脸跟踪缓存和完整检查点。结果区分 `completed` 与 `completed-needs-review`；存在主体丢失、保留原嘴或质量门禁警告时进入后者，允许预览/导出，但用户未逐次确认风险前不得进入自动发布提交。
- FR-010：视频生成完成后在“生成视频”页面自动选中结果并以内嵌播放器预览；“发布视频”页面列出 `completed` 及已由用户确认风险的 `completed-needs-review` 结果，并在存在字幕副本时把“无字幕干净版”和“带字幕版”作为同一任务的明确可选变体，标注质量/字幕状态。选择时复验任务终态、风险确认、变体类型、受管输出路径、文件存在性和指纹。首版使用确定性本地规则根据已确认文案生成可编辑标题、简介和相关话题，不额外引入未审计本地大模型；从所选视频抽帧，以本地模板生成 3 张独立封面并推荐评分最高的一张。
- FR-011：抖音和小红书分别使用应用受管的独立浏览器资料目录保存登录状态；用户在“发布视频”页面选择所需历史/当前视频和目标平台后，发布前完整展示平台、视频预览、封面和表单内容。
- FR-012：只有用户对当前所选视频和平台明确点击对应“一键发布”后，平台适配器才可打开官方创作者页面、上传视频与封面、填表并点击提交；每个平台独立校验域名、页面和字段。
- FR-013：平台登录、扫码、验证码、风控和用户确认触发暂停；提交状态被区分为未开始、准备中、等待用户、提交中、提交成功、失败、状态不确定和已审核（仅当页面可验证）。
- FR-014：创建音色与发布前提供授权/AI 内容声明；导出和发布元数据按实现时适用规则标识，同时保持“仅嘴部处理”的产品边界。不得删除、篡改、隐匿法定或平台要求的标识，不实现平台 AI 检测规避，也不承诺发布后不显示 AI 标签。
- FR-015：所有 A/B 视频、音色、文案、音频、输出、浏览器资料和任务状态默认本地保存；提供明确的受管数据删除，不上传到 TalkHero 或第三方推理服务。
- FR-016：首次使用某一 A 视频、主体身份、音频和生成参数组合时，完整生成前默认先生成 5～10 秒代表性预览；用户可确认、改选区间、调整输入后重试或显式跳过。完整结果的质量报告以时间轴展示主体丢失、保留原嘴、同步或融合风险区间，点击区间可循环预览；风险确认绑定结果指纹，结果变化后旧确认失效。
- FR-017：`apps/video` 以已确认原文初始化字幕正文、以最终生成音频为唯一时间基准，调用 `apps/inference` 中固定版本的本地 `faster-whisper` 取得时间锚点并对齐原文；识别结果只能辅助断句和定时，不得替换、增删或改写原文。用户可在“生成视频”页面显式编辑文字、断句和时间，编辑后形成新的用户确认字幕版本，再预览并导出 UTF-8 SRT；低置信、无锚点、时间重叠或越界片段必须显式提示并在烧录前确认。用户明确选择后，FFmpeg/libass 从干净口型结果生成独立 MP4 H.264/AAC 字幕副本，使用固定且可商用分发的字体；干净结果始终保留，字幕草稿或结果变化使旧烧录副本及发布确认失效。该链路完全本地、无按分钟费用，且不进入口型模型输入。

### 边界与异常（EDGE-*）

- EDGE-001：B 视频少于 10 秒、超过 60 秒、无音轨、有效人声不足、出现第二个有效说话人、背景音乐/回声/爆音导致不可用时拒绝创建；其他静默人物入镜不单独构成拒绝原因；可接受但非最佳的质量只给出警告并要求用户确认。
- EDGE-002：A 视频超过 3 分钟、损坏、不满足首版容器/编码/位深/色彩/FPS/分辨率矩阵、无可用主体或主体身份无法可靠建立/确认时拒绝生成。其他人物出现不构成拒绝原因，但任何其他身份不得进入口型蒙版或成为跟踪恢复候选。
- EDGE-003：文案为空、仅空白、超出 3 分钟可合理承载的时长，或目标音频长于/短于视频且无法通过已允许语速自然适配时，不静默裁字、重复画面或极端变速。
- EDGE-004：人脸持续过小、严重侧脸/背脸、遮挡、运动模糊、快速出画或身份跟踪置信不足时，保留原帧并报告区间；不得改用全脸生成或错误人物。
- EDGE-005：任何 renderer 传入的路径、ID、枚举、数值、URL、发布字段和任务操作都按不可信输入处理；拒绝越界路径、未知平台/域名、非法状态转换和非授权窗口调用。
- EDGE-006：同一 GPU/统一内存设备上的 CosyVoice2 与 MuseTalk 按能力串行加载和受控批量运行；OOM 不无限降低质量或循环重试，释放资源并给出可解释失败结果。CosyVoice2 可在 UI 明确显示“CPU 音频生成”后走经盲听确认质量等价的 CPU 路径，因为它只影响音频等待时间；MuseTalk 视频不得静默切换纯 CPU。任何会改变音频或画面质量的兼容模式必须由未来 Spec 定义并由用户明确选择。
- EDGE-007：模型、ASR、工具或浏览器资源下载中断、校验失败、版本不匹配、许可证信息缺失、解压路径越界或磁盘不足时不标记为可用，不执行损坏资源；重试只复用仍满足固定版本和哈希的已完成分项。
- EDGE-008：Worker 无响应、退出、协议版本不匹配、返回畸形消息或无法取消时，主进程终止受控进程、清理监听和句柄，并将任务置为可解释终态。
- EDGE-009：取消、应用退出或窗口销毁不会继续向已销毁 renderer 发送事件；不会删除源文件或已确认音色；中间目录按状态恢复或安全清理。
- EDGE-010：发布页面不在白名单域名、页面结构/字段不匹配、上传失败、验证码/扫码/风控出现或提交状态不确定时停止；提交按钮不得在一次用户操作中被重复点击。
- EDGE-011：发布成功只代表平台接收提交；除非页面明确返回审核状态，否则不得显示审核通过；状态不确定时不得自动重发。
- EDGE-012：平台发布资料始终绑定页面当前选择的生成任务、受管视频路径和文件内容指纹；切换历史/当前视频、封面或平台后旧确认失效，防止预览与实际发布内容错配。
- EDGE-013：删除音色时同时删除受管参考音频、转写和派生特征；被运行中任务引用时拒绝删除，失败时报告未删除项而不产生假成功。
- EDGE-014：日志、异常和测试 fixture 不包含完整文案、音色参考、视频内容、浏览器凭据、OAuth/会话值或可还原生物特征。
- EDGE-015：统一页面中的长任务、菜单切换和历史视频切换必须保持请求代次与进行中锁定；迟到响应不得覆盖较新的音色、文案、视频、平台或草稿选择，发布请求执行期间冻结参与本次提交的输入。
- EDGE-016：原音轨含前景人声或检测置信不足时，不开放环境声混音；不得以降低原音量、声道抵消或简单叠加冒充人声分离。短音频补齐区间仍需生成自然静止口型，不能恢复源视频中与新音轨不一致的原嘴动作。
- EDGE-017：字幕对齐不得相信 renderer 提供的任意时间轴、字体或滤镜参数；main/Worker 校验字幕文本大小、UTF-8 编码、时间单调性、片段边界、受管字体和输出路径。空字幕可选择关闭字幕；对齐失败、字幕未经确认、字体缺失、libass 不可用或烧录失败时保留干净结果和可恢复草稿，不把字幕副本标记成功。

### 非功能需求（NFR-*）

- NFR-001：正式目标平台为仍受厂商支持的 Windows 11 x64 与 macOS 15+ Apple Silicon arm64；Windows NVIDIA 完整推理最低 8GB 显存和 16GB 系统内存，Intel 正式档限经真机验收的 Core Ultra X9 388H/X7 358H 集成 Arc B390 且至少 32GB 系统内存，macOS 限 M1 及以上且至少 16GB 统一内存。Windows 10、Windows ARM、Intel Mac、Linux、低于对应内存门槛和纯 CPU 视频推理不在正式支持范围；同属 Core Ultra Series 3 但只配基础 `Intel Graphics` 的型号，以及其他未通过真实验收的 GPU，不宣称等价支持。
- NFR-002：性能数据用于支持范围、设备分级、剩余时间估算和发布承诺，不向用户展示内部机型排行榜，也不在缺少真机证据时宣传固定耗时。Windows NVIDIA 基准机为用户可提供的 Win11 RTX 4060 Laptop 8GB Y9000P；模型已安装、单主体、3 分钟 1080p 25/30fps 合格素材的产品目标为 6 分钟内完成，6～10 分钟必须继续优化并如实记录，经过本 Spec 允许的优化后仍超过 10 分钟则当前方案不得按正式商业性能标准交付并须重新评估。10 分钟是研发 go/no-go 线，不是运行中任务的自动终止时间；所有承诺必须以完整真机结果确认。Arc B390 与 Apple M1 及以上分别记录首次/缓存生成、峰值内存、温度降频和质量；未达门槛时不得以降质掩盖，须回写支持分级或模型方案。
- NFR-003：无字幕的干净口型结果除嘴部及自然融合所需最小邻域外不得出现可感知的主动修改；用户明确选择的字幕副本只允许在字幕安全区增加已确认文字，除此以外不得出现可感知主动修改。速度优化不得降低输出规格、扩大蒙版或跳过质量门禁。
- NFR-004：合格坐姿与正常走动素材均需达到可发布的身份稳定、无明显贴片边缘、无明显嘴部漂移/闪烁和可接受音画同步；“自然”不对不合格输入做无条件保证。
- NFR-005：媒体内容通过受控路径和只读媒体协议流处理，不通过 Electron IPC Buffer 传输；内嵌视频预览不得向 renderer 暴露任意文件路径，长任务不得阻塞 renderer 或 Electron main 事件循环。
- NFR-006：AI 推理仅在独立 Worker 中执行；协议、模型适配器和平台适配器可独立替换，业务模块不依赖第三方仓库内部布局或网页选择器细节。
- NFR-007：默认无按次付费 API；除模型/工具首次下载和用户明确的平台发布外，核心生成不需要外网。
- NFR-008：任务、文件和发布状态持久化具有原子性；崩溃、取消、磁盘不足和重启不会覆盖源素材或把半成品标成成功。
- NFR-009：用户数据、模型许可、平台登录和发布行为满足 AGENTS 与 PRD 的安全合规边界；外部写入必须可审计但日志不含敏感内容。
- NFR-010：新模块均有职责 README、最小公共类型与 IPC，稳定业务规则具备风险驱动自动化测试；硬件、模型质量和真实平台行为具备明确真实验收记录。
- NFR-011：同一固定输入在 CUDA、XPU/OpenVINO 与 MPS/Core ML 后端必须通过相同的音频内容、音画同步、身份稳定、嘴部外差分、失败片段和媒体规格门禁；允许浮点实现产生不可感知差异，不要求逐像素一致。Windows Intel 以 PyTorch XPU 为首选、OpenVINO 只用于已验证可转换且有收益的组件；macOS 以 PyTorch MPS 为首选、Core ML 同样只用于已验证组件；首版不依赖 NPU。跨平台加速不得采用跳帧、补帧、降低嘴部工作区分辨率、INT4 或整脸重绘。
- NFR-012：生产构建使用 Electron 官方仍维护的稳定大版本；升级必须经过现有窗口、IPC、媒体预览、自动更新、签名/公证配置和 Windows/macOS 安装回归。Electron renderer/main 不执行 AI 或逐帧媒体计算，避免 UI 内存和事件循环影响 Worker。
- NFR-013：客户安装过程只能下载预构建、版本化、已审计且哈希固定的平台资源包，不在客户机执行 `pip install`、`git clone` 或从可变分支解析依赖；macOS 包内及后下载的可执行文件满足签名、公证与 hardened runtime 验证，Windows 包和可执行文件满足代码签名与完整性验证。
- NFR-014：字幕初始正文必须逐字来源于用户确认原文，自动识别不得改写；只有用户显式编辑才能形成新的字幕正文版本。时间轴以最终音频为准；基础字幕在 Windows 与 macOS 使用同一受管字体、字号/边距规则和 libass 渲染契约，SRT 和烧录结果不依赖云服务。字幕对齐与烧录耗时单独计量并纳入用户可见剩余时间，不能计入或掩盖口型推理性能数据。

## 7. 数据与状态生命周期

- 受管根目录：由 main 基于 Electron `app.getPath('userData')` 解析，业务模块不能接受 renderer 指定的任意存储根。建议分为 `models/`、`voices/`、`jobs/`、`outputs/`、`cache/`、`browser/` 和 `runtime/`；最终物理命名在 Plan 中确定，但职责不得跨模块混用。
- 音色：以不可猜测 ID 标识；元数据包含显示名、创建/更新时间、模型及协议版本、参考媒体指纹、受管参考音频/转写/特征路径和试听状态。创建采用临时目录后原子提交；更新成功后替换，失败保留旧版本；删除遵循 EDGE-013。
- 生成任务：包含任务 ID、A 视频内容指纹、音色版本、文案摘要而非完整日志、已开放语音风格/语速、音轨策略、已确认主体身份摘要、试生成参数/结果指纹、各阶段状态、进度、检查点、干净/字幕输出变体及质量报告。任务状态机至少覆盖 queued、running、waiting-user、cancelling、cancelled、failed、completed、completed-needs-review；后者必须保存风险区间和用户确认状态。
- 音频：文案分段产物进入任务私有临时目录；只有通过内容/完整性检查并经用户确认的音频成为后续输入。文案或音色版本变化使旧音频确认失效。
- 视频：源 A/B 文件只读，不移动、不覆盖；输出写入受管输出或用户通过保存对话框明确选择的新路径。成功任务索引保存预览所需的受管输出相对路径和内容指纹；历史列表读取时复验文件，失效记录不作为可发布视频。临时帧、裁剪和缓存按任务隔离。
- 字幕：字幕草稿绑定最终音频指纹、确认原文版本和对齐器版本，保存分段文字、起止时间、置信/待确认状态，不保存额外识别正文替代原文；SRT 与字幕视频均为可删除的本地派生产物。字幕草稿、干净视频或字体/渲染版本变化后，旧字幕副本和发布确认失效。
- 跟踪缓存：键由 A 视频内容指纹、跟踪器版本及参数共同决定；任一变化使缓存失效。缓存只含必要坐标/特征，不保存额外完整视频副本。
- 发布草稿：绑定任务 ID、输出文件指纹、平台、文案、封面和确认版本；任一内容改变后发布确认失效。提交中状态持久化，重启后进入“状态不确定/待核对”而非自动重试。
- 浏览器资料：抖音与小红书分目录保存，仅平台适配器可访问；退出登录/清除平台数据由用户显式触发。不得复制日常浏览器 profile。
- store：只保存经过 schema 校验的索引、状态和设置，不保存媒体 Buffer、登录 secret 或可还原音色特征正文；大文件使用受管文件系统。
- 兼容：本项目默认不为未发布旧结构设计迁移。模型/协议版本变化必须拒绝不兼容档案或通过未来 Spec 定义升级，不静默猜测。

## 8. Electron 系统影响

- renderer UI/路由：保留“视频音色”“生成视频”“发布视频”和“本地推理”四个业务菜单，全部复用原系统 `SettingLayout` 并装配到 `config/menus.tsx`；不新增独立工作台或第二套配置窗口。“视频音色”页面只展示 B 视频授权选择及音色创建/更新；“生成视频”页面组合 voice/video 的最小 preload 公共面，先展示音色库、文案和音频试听，再展示视频质检/生成、当前结果预览和基础字幕编辑/导出/烧录；“发布视频”页面展示历史/当前视频选择及预览、封面、发布文案、平台选择和发布确认。renderer 不接触 Node、真实文件路径、模型、字体文件或浏览器凭据。
- main 业务与生命周期：四模块 main 入口按依赖顺序装配；inference 管理 Worker/工具/任务，voice/video/publish 各自校验业务状态；应用退出时停止任务、关闭 Worker 与受管浏览器，并持久化非成功终态。
- preload/IPC/公共类型：每个业务模块仅暴露所需命令与订阅；使用集中 channel 常量、带判别字段的结果、显式 operation 权限和严格参数解析；事件监听返回取消函数并在 webContents 销毁时清理。
- store、文件、网络：main 负责真实路径规范化、文件类型/大小/指纹、受管目录和原子写入；网络仅用于受控资源下载和用户触发的平台页面，域名有白名单；不暴露通用文件、命令或网络 IPC。
- 权限、硬件、原生能力：Windows 检测 NVIDIA/CUDA 或 Intel Arc/XPU/OpenVINO 与可用硬件编码器，macOS 检测 Apple Silicon/MPS/Core ML 与 VideoToolbox；Worker、FFmpeg 和浏览器均为受控子进程或运行资源。首版不新增摄像头、麦克风、辅助功能或全局 Hook 权限。
- `config/` 装配：按需更新 `config/main.ts`、`config/preload.shared.ts`/`config/preload.ts`、`config/routes.ts`、`config/window.ts`、`config/menus.tsx` 与 `config/dock.ts`；删除 `talkHero` 窗口声明，原 `setting` 窗口负责首次启动、Dock 激活、系统配置及全部业务页面。增加只承载创建/更新的 voice 配置路由，把 voice 音频内容组合进 video 生成路由，并恢复独立 publish 配置路由；不得新建第二套设置布局或跨模块搬迁 main 业务。
- 构建、签名、更新：Windows x64 与 macOS arm64 分别构建；需要验证 Electron 受支持版本、新 JavaScript 依赖、三个平台 Worker 启动路径和运行包选择可被 electron-vite/electron-builder 正确处理，但模型、运行环境和下载资源不直接提交到安装包。本 Spec 不修改签名身份、公证凭据、更新源或正式发布操作，只允许为 Electron 升级和平台资源装配做必要配置兼容。

## 9. 平台兼容

- macOS 15+ Apple Silicon：正式完整本地候选平台，仅支持 arm64 M1 及以上且至少 16GB 统一内存；以受管 Python 3.11 arm64 + PyTorch MPS 为首选，Core ML 只用于探针证明兼容且有收益的组件。必须验证 CosyVoice2（MPS 或明确的 CPU 音频路径）、MuseTalk、人物跟踪、VideoToolbox、取消/OOM恢复、签名后 Worker 启动和首版媒体矩阵输出；通过阶段 0 和真实 AC 前保持“候选/未验证”，不因框架可安装就宣称完整支持。
- Windows 11 x64：正式目标平台；NVIDIA CUDA 档最低 8GB 显存、16GB 系统内存，以用户可提供的 RTX 4060 Laptop 8GB Y9000P 为首个基准。Intel 候选档限 Core Ultra X9 388H/X7 358H 集成 Arc B390 且至少 32GB 系统内存，以 PyTorch XPU 为首选、OpenVINO 只用于已验证组件。其他 Panther Lake 型号只有在实际 GPU、内存、驱动、算子、性能和质量均通过同一验收后才可加入支持矩阵；所有档均须先通过阶段 0 才能对外标为正式支持。
- Windows 10：明确不支持；环境探测不得把它标记为正式目标，也不为其维护旧驱动、旧 Python/PyTorch 或安装包兼容分支。
- Windows ARM、Intel Mac、Linux：明确不支持；不得因 Electron 或第三方模型自身可启动而对外开放未验证入口。

## 11. 功能阶段（What）

### 阶段 0：商业与三后端可行性门

- 用户可观察目标：无；本阶段是生产实现前的内部阻断门，不在产品界面展示实验数据。

## 13. 验收标准（AC-*）

### AC-001：环境检测与受管资源

- 关联需求：FR-001、FR-002、FR-017、EDGE-005～EDGE-008、EDGE-017、NFR-001、NFR-005～NFR-014。
- 前置条件：分别准备 Windows 11 NVIDIA、Windows 11 Core Ultra X9 388H/X7 358H 集成 Arc B390、macOS 15+ Apple Silicon 16GB 及不支持平台，并覆盖资源完整、缺失、校验失败和磁盘不足状态。
- 操作：打开原系统 `setting` 窗口的“本地推理”菜单，查看预计下载量/磁盘/许可证后点击一次“安装所需资源”，并分别执行取消、断网重试和损坏修复。
- 可观察预期：一次点击后无需命令行或逐项手工安装即可只安装匹配的 `windows-cuda`、`windows-xpu` 或 `macos-mps` 资源；UI 显示真实平台、加速后端、内存/显存、总进度和分项状态；互斥后端不混装；只执行固定来源且逐项校验通过的资源；失败进入可解释终态并可复用合格分项；系统级驱动只给出引导；Windows 10、低内存和不支持设备不会被误报可用；renderer 不能指定命令、下载域名或任意安装路径。

### AC-002：从 B 视频创建可复用音色

- 关联需求：FR-003～FR-004、FR-014～FR-015、EDGE-001、EDGE-005、EDGE-013～EDGE-014、NFR-007～NFR-010。

- 操作：进入独立“视频音色”菜单，确认授权，创建、试听、命名音色；随后关闭应用并重新打开；再更新和删除音色。
- 可观察预期：“视频音色”页面只承载创建或更新音色所需的授权素材选择、名称和操作，不出现文案音频制作；合格样本生成可试听且重启后可用的音色档案；后续不要求 B 视频；非法样本不创建可用档案；更新失败保留旧音色；删除清除受管参考及特征且不泄露敏感日志。

### AC-003：独立文案生成正确音频

- 关联需求：FR-005、FR-009、EDGE-003、EDGE-006～EDGE-009、NFR-004～NFR-008。

### AC-004：A 视频质检与人物锁定

### AC-007：任务进度、缓存、取消与故障恢复

- 可观察预期：状态转换合法且 UI 不假死；资源最终释放；不把半成品标记成功；无风险结果进入 `completed`，含风险区间结果进入 `completed-needs-review` 且确认前不能自动提交；输入一致时复用缓存，输入变化时缓存和旧风险确认失效；重启后提交中/运行中任务进入安全可恢复状态。

## 16. 发布、兼容与恢复

- 现有用户/数据：新增模块使用独立 store 与受管目录，不迁移或重写 core/auth/secret 数据；原 `setting`、login、pay 窗口和认证能力保持可用，未发布的独立 `talkHero` 窗口定义直接移除且不提供兼容入口。
- 不可逆变化：真实平台提交是外部不可逆操作，只能由当前任务的明确点击触发；音色删除会删除受管生物特征文件，必须确认目标且运行中引用时拒绝。
- 模型/工具：首次下载可取消和重试，只有哈希与版本通过后原子标记可用；损坏或不兼容资源隔离，不删除用户源媒体。
- 任务恢复：源文件永不覆盖；中间产物按任务隔离；崩溃/退出后非成功任务恢复为安全状态，由用户选择继续、重试或删除。
