## 1. 背景与目标
启动时自动更新输出 `Cannot download differentially, fallback to full download`，具体原因是多段 Range 下载预期 `multipart/byteranges`，实际返回 `application/zip`。当前 electron-updater 6.8.9 捕获该异常后会尝试完整下载，此日志本身不能证明应用启动失败或完整下载失败。

目标：开发配置和打包配置统一使用单段 Range 差分下载，兼容不返回 multipart 响应的服务；保留现有更新行为和完整下载回退。交付必须区分本地协议验证与真实更新服务、真实平台验证。

## 2. 模块归属
- 类型：更新下载兼容性 Bug 修复，高风险边界中的小范围配置变更。
- 归属：apps/core 自动更新基础设施及根目录更新配置。
- 不涉及 voice、video、inference、publish 业务模块。

## 3. 范围与非范围
### 范围内
- 在 dev-app-update.yml 与 electron-builder.yml 的 generic provider 配置中显式禁用多段 Range 请求。
- 增加有价值的下载协议回归验证，完成相关门禁与独立审查。
- 仅在更新配置边界说明需要同步时，最小更新 apps/core/README.md。
### 范围外
- 禁用开发环境更新、修改检查频率、自动下载或安装策略。
- 更换更新源、TalkHero 品牌迁移、修改服务端/CDN、升级依赖、修复其他更新状态或 IPC 问题。
- 提交、推送、发布、上传、真实更新安装。
### 影响边界
- 开发运行直接读取的更新配置，以及未来打包产物内生成的更新配置；已安装的旧客户端不会因此自动改变。
### 禁止修改（仅必要项）
- 更新 URL、签名与公证配置、发布脚本、版本号、生成文件及无关本地数据。

## 4. 当前行为
- initUpdater 在开发环境设置 forceDevUpdateConfig，启用自动下载；默认启动约 5 秒后检查更新，后续每 10 分钟检查。
- 两份 generic provider 配置未指定 useMultipleRangeRequest，现有依赖对当前 URL 默认启用该选项。
- 服务返回类型与多段下载器要求不符时，依赖记录错误并尝试完整下载。
- 当前配置仍使用原脚手架更新源；其是否适合 TalkHero 正式分发属于独立决策，本次不改变。
- 尚未实测服务端单段 Range 能力，也未证明用户此次完整下载最终结果。

## 5. 目标行为与流程
### 主流程
具备旧安装包缓存与可差分的新版本 → 自动或手动触发既有检查 → 更新器分别请求所需单个字节区间 → 服务返回合法 206 与 Content-Range → 重建并校验新安装包 → 进入既有下载完成流程。
### 关键失败流程
单段请求失败、响应不可用或无法完成差分时，继续使用依赖既有的完整下载回退；完整下载或校验失败仍按现有错误流程报告，不伪造下载完成。
### 恢复流程
沿用既有更新重试入口；不新增重试、清理或兼容分支。

## 6. 需求清单
### 功能需求（FR-*）
- FR-001：开发与打包使用的 generic provider 均显式配置 useMultipleRangeRequest: false。
- FR-002：有可用差分输入时，实际差分请求中的 Range 只含单个字节区间；支持单段 Range 的服务可完成内容重建与校验。
- FR-003：保留依赖已有完整下载回退、完整性检查和应用现有更新状态上报。
### 边界与异常（EDGE-*）
- EDGE-001：没有旧包缓存等无法差分的情况仍可走既有完整下载流程。
- EDGE-002：单段 Range 不支持或差分失败时，不保证消除所有差分错误日志；必须真实验证并披露，不能通过屏蔽日志伪装成功。
- EDGE-003：完整下载或完整性校验失败不得报告为成功；此次不新增或重构错误状态逻辑。
### 非功能需求（NFR-*）
- NFR-001：不新增依赖，不修改更新 URL、签名校验、版本号、检查与安装策略。
- NFR-002：测试使用无个人信息的合成数据与临时目录；真实网络验证限制下载量，不触发安装、不写远端、不使用生产凭据。
- NFR-003：单段请求可能增加请求次数；不承诺下载提速。未实测的平台、真实服务或安装链路必须明确标记未验证。

## 7. 数据与状态生命周期
- 输入仍为既有版本清单、blockmap、缓存旧包及更新包；输出仍为更新器下载产物与既有状态。
- 无新增持久化键、数据格式、CRUD、迁移、失效策略或用户数据清理。
- 临时测试产物在验证后清理；不删除真实更新缓存。

## 8. Electron 系统影响
- renderer UI/路由、main 生命周期、preload/IPC/公共类型、权限/硬件/原生、config 装配：无接口变更。

- 构建/签名/更新：只调整 generic provider 下载选项；须验证配置能被工具链接受并进入打包更新配置。签名、公证与安装不在本次执行授权内。

## 13. 验收标准（AC-*）
### AC-001：两种运行配置均使用单段请求
- 关联需求：FR-001、FR-002。
- 前置条件：使用仓库实际配置与当前 electron-updater，准备需要多个差分片段的合成新旧文件；本地 HTTP 服务仅支持单段 Range。
- 操作：分别由开发配置和打包 publish 配置取得 provider 下载策略，执行真实差分下载器。
- 可观察预期：实际 Range 请求不含逗号；新文件内容及摘要正确；无 multipart 类型错误。旧配置应在相同场景正确复现失败。

### AC-002：失败与完整下载路径保留
- 关联需求：FR-003、EDGE-001、EDGE-002、EDGE-003。
- 前置条件：隔离临时目录与 HTTP 服务，覆盖无可用旧包、差分请求失败、完整下载失败或内容损坏。
- 操作：验证依赖已有的回退与校验流程，以及其与既有应用错误上报的连接。
- 可观察预期：无法差分时仍可尝试完整下载；正确完整包可验证通过，下载失败或摘要不符不会产生成功结果；不新增回退实现或屏蔽日志。

### AC-003：真实运行与配置范围
- 关联需求：FR-001、NFR-001、NFR-002、NFR-003。
- 前置条件：受支持 macOS 和可访问的真实更新服务；使用隔离、安全的验证方式。
- 操作：验证真实服务单段 Range 响应、真实 Electron 下载行为及打包配置传递；审查最终 diff。
- 可观察预期：记录服务实际状态、响应区间及字节数、运行环境和结果；URL、签名及安装策略无变更；不可执行项记录原因，不宣称完整安装或 Windows 验证通过。
